# Test fixtures

`arm_level.urdf` and `arm_tilt30.urdf` are the robot model as the arm publishes it on
`/arm/robot_description`, rendered by kinova-gen3-ros2's `kinova_gen3_render`. They are
committed as rendered, plus one trailing newline (the `end-of-file-fixer` hook).

- Image: `kinova-gen3-ros2:review-sim` on abra, ID
  `sha256:b8a5a209e2c8a0c3404db4a4d54fd31235e2f4e78570c01651ab2edecc13f895`, built
  2026-10-16, against kinova-gen3-driver `dev` @ `e439d30`. Built from the
  kinova-gen3-ros2 `feat/tilted-arm-mount` tree at `e140639`; the description and renderer
  are unchanged since `6dfb507`. Its `camera` xacro arg defaults to false, so the bracelet
  mesh is `bracelet_no_vision_link.dae` (no Kinova vision module).
- Rendered 2026-10-18.

Mount files:

```yaml
# level.yaml
robot: fixture_level
rpy_deg: [0, 0, 0]
```

```yaml
# tilt30.yaml
robot: fixture_tilt30
rpy_deg: [0, 30, 0]
```

Commands (from the directory holding the mount files):

```bash
docker run --rm --network none -u $(id -u):$(id -g) -v $PWD:/w -w /w kinova-gen3-ros2:review-sim \
  bash -c "source /module_ws/install/setup.bash && python3 -m kinova_gen3_render --mount /w/level.yaml --out /w/arm_level.urdf"
docker run --rm --network none -u $(id -u):$(id -g) -v $PWD:/w -w /w kinova-gen3-ros2:review-sim \
  bash -c "source /module_ws/install/setup.bash && python3 -m kinova_gen3_render --mount /w/tilt30.yaml --out /w/arm_tilt30.urdf"
```

The two files differ only in `arm_base_joint`'s origin: `rpy="0.0 0.5235987755982988 0.0"`
in the tilt fixture.

The fixtures are used as rendered: the 2F-85's mimic joints carry no `<limit>` in them, and
`urdf_model.prepare_urdf` fills each from the joint it follows before cuRobo reads the
model. The robot config locks the gripper by its actuated joint only
(`arm_robotiq_85_left_knuckle_joint`); cuRobo holds the five mimics with it.

## The robot config's inputs

`robot_gen3_2f85_nvidia.yaml` is the pre-upstream-model robot config: the audit-tuned
spheres on NVIDIA's link frames and names. `robot_gen3_2f85_moves.yaml` is GENERATED by
`make bake`: the 4×4 that moves each gripper link's spheres from NVIDIA's model onto
`arm_level.urdf` at q = 0 (the arm links' moves are identity, and the bake asserts it).
`test_bake_rebuilds_the_committed_robot_config` runs the bake's pure step,
`build_robot_config`, on the two and expects the committed `robot_gen3_2f85.yaml`.
Regenerate with `make bake`, which expects no diff in either generated file.
